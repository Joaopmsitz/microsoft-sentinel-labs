## 🎯 Objective

Configure Microsoft Sentinel to collect, monitor, and investigate Windows Security Events from a Windows virtual machine using Azure Monitor Agent (AMA).

The lab focuses on endpoint monitoring, security event ingestion, KQL-based investigation, and automated incident detection.

## ⚙️ Configuration

The **Windows Security Events via AMA** connector was configured in Microsoft Sentinel.

A Data Collection Rule was associated with the Windows virtual machine and configured to collect Windows Security Events.

The DCR uses the `Microsoft-SecurityEvent` stream and sends the telemetry to the Log Analytics workspace.

The following Windows event sources were collected:

* Windows Security Events
* AppLocker EXE and DLL events
* AppLocker MSI and Script events

---

## 🔎 Validation

### 1. Endpoint Validation

Security Event ID **4688 — Process Creation** was first validated directly on the Windows virtual machine.

The following PowerShell command was used:

```powershell
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4688} -MaxEvents 5
```

The command successfully returned Windows Security Events generated by the endpoint.

This confirmed that the Windows Security log was generating process creation telemetry locally.

---

### 2. Microsoft Sentinel Validation

The same event type was queried in the `SecurityEvent` table using KQL:

```kusto
SecurityEvent
| where TimeGenerated > ago(1h)
| where EventID == 4688
| order by TimeGenerated desc
| take 20
```

The query successfully returned Event ID 4688 in Microsoft Sentinel.

This confirmed the ingestion pipeline from the Windows endpoint to Microsoft Sentinel.

---

## 🚨 Analytics Rule

A custom Microsoft Sentinel Analytics Rule was created to detect Windows process creation events.

**Rule:** `Lab 03 - Process Creation Monitoring`

**Severity:** Informational

**Frequency:** Every 5 minutes

**Lookup period:** Last 5 minutes

**Trigger condition:** More than 0 results

**Incident creation:** Enabled

The rule uses the following KQL query:

```kusto
SecurityEvent
| where EventID == 4688
| project
    TimeGenerated,
    Computer,
    Account,
    NewProcessName,
    ParentProcessName,
    CommandLine
```

The rule successfully generated Microsoft Sentinel incidents when process creation events were detected.

---

## 🕵️ Incident Investigation

A generated incident was assigned for investigation and validated against the endpoint activity.

The detected process creation was confirmed to be legitimate activity generated during the lab.

The incident was classified as:

**Benign Positive**

and subsequently resolved.
