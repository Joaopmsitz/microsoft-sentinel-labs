# Lab 03 — Endpoint Monitoring with Microsoft Sentinel

## 🎯 Objective

Configure Microsoft Sentinel to collect and investigate Windows Security Events from a Windows virtual machine using Azure Monitor Agent (AMA).

The lab focuses on endpoint monitoring, security event ingestion, and KQL-based investigation.

---

## 🧪 Lab Environment

* Microsoft Sentinel
* Azure Log Analytics
* Azure Monitor Agent (AMA)
* Windows Virtual Machine
* Data Collection Rules (DCR)
* Windows Security Events
* KQL (Kusto Query Language)

---

## 🏗️ Architecture

```text
Windows VM
    ↓
Azure Monitor Agent (AMA)
    ↓
Data Collection Rule (DCR)
    ↓
Microsoft-SecurityEvent
    ↓
Log Analytics Workspace
    ↓
SecurityEvent
    ↓
Microsoft Sentinel
```

---

## ⚙️ Configuration

The **Windows Security Events via AMA** connector was configured in Microsoft Sentinel.

A Data Collection Rule was associated with the Windows virtual machine and configured to collect Windows Security Events.

The DCR uses the `Microsoft-SecurityEvent` stream and sends the telemetry to the Log Analytics workspace.

The following Windows event sources were collected:

* Windows Security Events
* AppLocker EXE and DLL events
* AppLocker MSI and Script events

---

## 🔎 Validation

### 1. Endpoint Validation

Security Event ID **4688 — Process Creation** was first validated directly on the Windows virtual machine.

The following PowerShell command was used:

```powershell
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4688} -MaxEvents 5
```

The command successfully returned Windows Security events generated by the endpoint.

<img width="1149" height="562" alt="image" src="https://github.com/user-attachments/assets/8c71e3aa-4850-4015-9c1b-8739947a4179" />


This confirmed that the Windows Security log was generating process creation telemetry locally.

---

### 2. Microsoft Sentinel Validation

The same event type was then queried in the `SecurityEvent` table using KQL:

```kusto
SecurityEvent
| where TimeGenerated > ago(1h)
| where EventID == 4688
| order by TimeGenerated desc
| take 20
```

The query successfully returned Event ID 4688 in Microsoft Sentinel.

![SecurityEvent 4688 in Microsoft Sentinel](images/sentinel-securityevent-4688.png)

This confirmed the complete ingestion pipeline:

```text
Windows Security Event
        ↓
Azure Monitor Agent
        ↓
Microsoft-SecurityEvent
        ↓
Log Analytics
        ↓
SecurityEvent
        ↓
Microsoft Sentinel
```
